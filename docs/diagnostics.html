Local startup and temporary runtime storage

The runtime launcher detects WSL workspaces on Windows-backed mounts. It extracts a pinned archive of public installed tools to Linux temporary storage, then runs the coordinator in a private mount namespace at the original workspace paths. Random temporary paths do not enter action identities. Results and the action cache stay in the workspace; credentials and raw traces are never packed.

Offline controls cover real bind mounts, attestation/action-key invariance across different temporary paths, mutation rejection and cleanup. The first run packs installed runtime dependencies; later runs reuse the verified archive. Refresh the archive explicitly after updating installed tools. Launcher source and storage configuration are runtime-attestation inputs; unrelated scripts and random temporary names remain outside those inputs. These are environment performance repairs, not new model observations or corrected historical scores. Model reasoning, output budgets and provider latency remain separate limitations.

Capability attempts use a stable logical trial in the inference action and an action-addressed result directory. A matching legacy attempt retains its original path and key. Changed runtime/provider inputs select a separate immutable attempt; the same stopped action remains blocked. Reports retain all actions and require explicit action selection when several share one configured cell; rendering never probes a provider to choose a current result.

Warm verification and cold regression are separate

make check or make check-warm checks accepted cache receipts, recomputes prepared action keys, verifies frozen packages and saved artifacts, and freshly seals dependency bytes. It performs no builds, grading, runtime inventory, or model calls. Missing, changed or corrupt inputs fail instead of silently starting cold work. make check-cold explicitly runs the full build/fixture/corruption/transport regression suite; it records each command duration separately. Fresh runtime/provider attestation still belongs to an actual model run.
