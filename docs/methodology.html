How scores are calculated

Models receive the frozen binary, task instructions and read-only analysis tools. Hidden tests and compiler feedback are unavailable during inference.

Capability / What is checked
CapabilityWhat is checked
Native languagesSubmitted source is compiled and checked against hidden exact-output tests. Full marks require every check to pass.
LocalizationFunction roots, instruction ranges, references and call chains are compared with frozen targets. L1 uses top-1 success, L2–L4 use F1, and L5 uses full-chain success.
ReconstructionRecovered source and code-generation controls are compiled and tested for exact values, memory effects and return behavior.
Types / ABISubmitted types, layouts and calling conventions generate probes against unchanged original callers and callees. Defined values and protected memory are checked.

Each overview axis is the mean of graded case percentages, with equal weight per case. Sample counts are shown beside scores. The native comparison also reports a check-weighted rate; it is a different measure.

Localization answers with unresolved format errors remain ungraded. A confirmed location mismatch requires an admitted answer. Other task kinds retain their saved artifact-admission rules.

Measurement scope

The catalogue contains 195 cases per model: 42 native language cases, 9 localization cases, 104 reconstruction cases and 40 type/ABI cases. Compiler and language variants are distinct cases. Unpacking is planned and contributes no score or denominator.

Saved results and missing scores

Valid cached grades count once per model and configured task, regardless of run date. The saved selection is used; results are never chosen by highest score. A later failed or ungraded attempt does not erase an eligible grade.

Not started, paused, budget-stopped and API-failed attempts remain ungraded. A saved deadline non-pass is a measured zero. Complete answers can retain a correctness grade even when they exceeded their spending limit.

Task limits and comparison limits

Limits belong to each saved attempt. Recent runs used a 65,536-token response allowance and adaptive limits based on twice the complete-answer mean for the same model and task type. Historical attempts retain their original limits. Codex OAuth records observed thresholds rather than a provider-enforced response cap.

Models use Codex, DeepSeek Harness or ZCode routes. Prompts, budgets, providers and covered subsets can differ. Shared-case charts align task coverage; they do not establish equal-budget or model-only rankings. Concurrent work can affect elapsed time.

These are bounded task observations. They do not certify arbitrary program recovery, every language feature, binary-compatible replacements or independent task-validity review.

Historical source readability is a stored AI review and is separate from correctness. Missing reviews do not count as zero.

Usage and estimated cost

Usage includes unique attempts, including failures. Cache reuse and offline regrading add no model usage. Missing usage remains unknown; displayed costs are published-rate estimates. GPT costs are API equivalents, not measured subscription charges.
