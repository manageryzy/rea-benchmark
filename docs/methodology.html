Benchmark and reporting workflow

  1. 01Frozen benchmark cases

    Public ELF, language contract, prompt, tools and budgets

  2. 02Model + harness

    DeepSeek / GPT in DeepSeek Harness; GLM in ZCode

  3. 03Ghidra evidence

    Restricted functions, assembly, xrefs, strings and bytes

  4. 04Native grading

    Unchanged source → isolated compiler → hidden exact checks

  5. 05Saved records

    Answer, evidence, usage, grades, source reviews and pricing

  6. 06Global HTML report

    make reports → charts, case pages, JSON, CSV and portable ZIP

Model inference ends before grading; hidden tests and compiler feedback never return to the model. Steps 01–04 run only through an explicitly authorized benchmark command. Report generation reads step 05 offline and never launches another experiment.

Models receive only the frozen public ELF, prompt and restricted read-only REA tools. Hidden sources, tests, execution, shell access and compiler feedback are unavailable. Unchanged submissions are compiled and independently checked offline. Correctness, whole-program success, function points and five-dimension source readability are separate measures. Coordinating-AI readability reviews are not an independent blind panel.

Cached attempts are validated against effective binary, prompt, tool, model and harness inputs. Missing measurements remain pending; environment failures are not zero model scores. Cases run sequentially within each model with up to three model queues sharing the host, which can affect runtime.

Public report reproduction

The normal local report command refreshes an allowlisted summary cache from saved records. Local rendering blocks network and process creation and needs no provider credentials, model runtime, raw traces or downloaded toolchain. The generated site is committed under master/docs for GitHub Pages. Only HTML, CSS and JavaScript are deployed; raw JSON, source exports, answers, archives and reasoning are absent.
