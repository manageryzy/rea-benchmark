# Typed observations in the global report

`make reports` reads saved L/C/T attempts and regenerates the private report,
sanitized snapshot, public preview and `docs/` Pages files. It performs no
preparation, compilation, candidate execution, authentication or provider calls.
The existing global navigation links to `capabilities.html`; there is no dated
runner or report for this implementation work.

Run `make check-capability-measurements` for the saved-record controls. The
source-bound receipt is separate from the task-preparation control receipts. Local
fixtures cannot become model observations.

## Inventory and measurement scope

The collector enumerates registered declarations before inspecting saved
attempts. Configured cells are selected models × selected task definitions.
Enabled cells form the current scheduled denominator. Disabled, unprepared,
stale, corrupt, unstarted, interrupted and infrastructure-failed conditions have
distinct states. Missing or infrastructure-invalid work never becomes a zero
correctness observation. An artifact rejected by a valid grader is a failed
submission and is scored according to that contract.

The inventory binds its nonsecret configuration and public package identities
to a snapshot digest. It is explicitly `configuration_snapshot_only`: this is
**not** proof of an immutable denominator registered before historical model
execution. New capability runs have a separate [immutable pre-run registration](capability-registration.md),
shown alongside this inventory. Historical observations are never retroactively
registered, and no capability is released by either view.

Public task identifiers come from the verified frozen public manifest. Pending
tasks use opaque provisional identifiers. Private presence/absence labels,
locations, layouts, oracle values, candidate code, reasoning, errors, provider
JSON and local paths are excluded from publication. The local collector checks
frozen package bytes and binds selected grades to the saved answer, task
contract, private specification digest and artifact manifests. It does not
reconstruct missing historical runtime evidence from the current installation.

## Separate scores and coverage

L1 uses top-1 success. L2–L4 retain F1, precision and coverage. L5 uses existing
full-chain success and retains its root/node/edge diagnostics. C/T use the
capability-specific passed/total fraction. Nonapplicable facts remain null.
No overall capability ranking is calculated.

The explicit `typed-family-macros-v2` policy adds L6 instance F1, precision and
coverage, keeping it separate from whole-task success. T7 uses the fraction of
checks across both original-endpoint directions; every selected check must pass
for whole-task success. A coincidental correct result at one nonce does not turn
a wrong boundary into a passed task. Earlier v1 policy records remain readable.
`optimized_mix_locations_v1` and `native_aggregate_interfaces_v1` each group
their related build conditions; they do not create independent semantic families.
JSON descriptions have no source-readability score. Native ABI observations keep
their separate `host_native_abi_return_v1` provenance rather than inheriting
general C executor or historical native-frame certification.

For each model, condition and capability, compute a mean across build/ABI
variants within each family, then across related families within a lineage,
then equally across lineages. All existing integer-record ABI forms share
`integer_record_interfaces_v1`; their three wrappers are not three independent
semantic lineages. Recovery, original-language recovery, counterfactual and
full-semantics generation profiles remain separate conditions.

An observed-subset macro shows its family/lineage coverage. A full-denominator
macro remains null until every scheduled cell has a grade. A shared-case macro
uses only identical graded public packages across all selected models. Neither
partial coverage nor extra variants quietly increases a family's weight.

Source readability retains the five 0–2 dimensions, source digest binding,
review count and recorded provenance. Structured artifacts have no source
readability score. A missing/invalid review cannot remove a behavioral grade.
The collector does not establish independent review or invent confidence
intervals.

## History and accounting

One inference fingerprint identifies one saved observation. Cache copies and
offline grading revisions do not create additional observations or charges.
Retired configurations remain in history and expenditure, separate from the
current comparison. Selected grading uses `selected-grade.json`; all valid
other revisions remain visible. Corrupt revisions are counted as gaps.

Current cost summaries use the request ledger and the currently saved price
revision under an explicit `current_saved_pricing` policy. Saved accounting
revisions retain their own IDs and versions; they are never selected by filename
order. Their cost/ledger payloads are checked against the original Merkle input
tree. A corrupt accounting revision cannot remove a valid behavioral score.
Unknown usage is not zero, incomplete usage survives successful grading, and
known subtotals are not total bills or provider invoices.

The read-only collector and public schema are report-stage dependencies only.
They do not enter inference or candidate-grading action identities. Private
reports may read explicitly bound frozen task packages/specifications and
accounting Merkle nodes; they never load installed analysis or compiler images.
The original-build projection verifies saved build AC/CAS records and compiler
profile manifests. It reports the original compiler version, standard,
optimization, library, architecture, linkage, stripping and disclosed ABI,
separately from candidate grading. It does not execute a compiler or read its
installation. Private macros, measured ABI answers, source paths and full
commands stay out of the public snapshot. Standalone public rendering uses only
the allowlisted snapshot and static assets.
